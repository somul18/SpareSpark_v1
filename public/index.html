How parts come in

  1. Procurement Agent drafts a PO when neither the part nor an approved substitute is in stock. It orders the failed part, or its documented successor if the part is obsolete, from the vendor on file at the reorder quantity.
  2. Procurement Coordinator approves the PO. The repair stays paused until then.
  3. Vendor ships. The vendor or ERP reports the shipment with a tracking number (POST /api/purchase-orders/:id/ship). In the demo this is simulated a few seconds after approval.
  4. Warehouse receives the goods: click Receive and confirm the quantity. Stock is added to the part's bin, one unit is reserved for the waiting incident, and the Resolution Agent dispatches the technician.

ServiceNow plugin

SpareSpark runs on its own. The optional ServiceNow plugin sends robot incidents here and receives stage updates back as work notes, so coordinators can approve parts from either side.

  1. Import servicenow-plugin/dist/sparespark-servicenow-update-set.xml into your instance (System Update Sets > Retrieved Update Sets > Import Update Set from XML), then preview and commit.
  2. Set the system properties sparespark.base_url, sparespark.api_key and sparespark.inbound_token.
  3. Point SpareSpark's SPARESPARK_WEBHOOK_URL at the instance's SpareSpark Scripted REST API /events resource (the full path is shown on the API record).
